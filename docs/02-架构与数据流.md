# 02 · 架构与数据流

## 1. 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  接入层  FastAPI  /collect  /publish  /tasks  /items         │
│          命令行  run_demo.py  |  定时任务  scheduler          │
└───────────────────────────┬─────────────────────────────────┘
                            │ 任务投递（task_id）
┌───────────────────────────▼─────────────────────────────────┐
│  调度层  Queue (Redis / 本地 SQLite 表)  +  Worker 池          │
│          限速器 RateLimiter（按平台、按账号）                  │
│          重试策略 指数退避 / 死信队列                          │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  采集层  Collectors（每个平台一个适配器，统一接口）            │
│   taobao.py  jd.py  alibaba.py  +  mtop.py（签名/会话复用）   │
│   输出：RawItem（原始 JSON，原样保留，便于回溯）               │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  归一化层  Normalizer → Item（跨平台统一模型，见 schema/）      │
│   字段对齐 / 单位统一 / 富文本清洗 / 去水印标记                │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  素材层  MediaPipeline                                        │
│   下载（带 Referer）→ 校验尺寸 → 转存图床/本地 → 生成 800x800   │
│   → 详情图切分/拼接 → 记录 hash 去重                          │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  映射层  Mapper（项目核心，占 70% 工程量）                     │
│   CategoryMapper   源类目 → 目标类目（表 + 相似度 + 人工确认）  │
│   PropertyMapper   属性名/属性值/品牌 → 目标 ID                │
│   SkuRebuilder     SKU 矩阵重建 + 属性顺序对齐                 │
│   TextSanitizer    极限词/品牌词/联系方式清洗                  │
│   Validator        必填校验、图片数量、价格区间                │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  发布层  Publishers（每个目标平台一个适配器）                  │
│   taobao_pub.py（开放平台 / 后台模拟 双通道）                  │
│   jd_pub.py  alibaba_pub.py                                   │
│   输出：PublishResult（成功/失败原因/商品ID/草稿ID）           │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  存储层  SQLite/PostgreSQL（元数据） + 本地目录/OSS（素材）    │
└─────────────────────────────────────────────────────────────┘
```

## 3. 数据流时序（单条商品）

```
用户 → POST /collect {platform: taobao, item_id: 6xx}
  1. 建 task 记录（status=pending）
  2. Worker 取任务
  3. Collector: mtop 调 pcdetail → 拿 item/skuBase/skuCore/props/apiStack
  4. Collector: 从 apiStack 提 descInfo → 调 getdesc 拿详情 HTML（可选）
  5. Normalizer: 组装 Item（标题/价格区间/图片列表/规格树/参数表/详情图 URL）
  6. MediaPipeline: 并发下载主图+详情图 → data/media/<id>/ → 回填本地路径
  7. Storage: 写 data/items/<id>.json + SQLite 索引
  8. 返回 item 预览（前端展示"抓到了什么"）

用户 → POST /publish {item_id, target: taobao, shop: myshop, mode: draft}
  1. Mapper: 源类目 → 目标类目（查表；未命中则走候选列表让人选）
  2. Mapper: 属性映射 + 品牌映射 + SKU 重建
  3. Sanitizer: 标题清洗、详情图去外链
  4. Validator: 必填校验 → 不通过直接返回缺什么
  5. Publisher: 上传图片到图片空间 → 拿 URL → 组载荷 → 提交
  6. 记录 PublishResult（商品ID / 草稿ID / 错误码 / 原始响应）
```

## 4. 存储设计

```
data/
├── raw/<platform>/<item_id>.json      # 原始响应，永不覆盖（回溯用）
├── items/<item_id>.json               # 归一化后的 Item
├── media/<item_id>/
│   ├── main_0.jpg ... main_n.jpg      # 主图（原图 + 800x800 版本）
│   ├── desc_0.jpg ...                 # 详情图（从详情 HTML 抽出）
│   └── manifest.json                  # hash / 尺寸 / 源 URL / 转存后 URL
├── mapping/
│   ├── category_map.yaml              # 源类目 → 目标类目
│   ├── property_map.yaml              # 属性名/值映射
│   └── brand_map.yaml                 # 品牌名 → 目标品牌 ID
└── app.db                             # SQLite：tasks / items / publish_logs
```

SQLite 表结构：

```sql
CREATE TABLE tasks (
  id TEXT PRIMARY KEY, platform TEXT, item_id TEXT,
  status TEXT,            -- pending|running|done|failed
  error TEXT, created_at TEXT, updated_at TEXT
);
CREATE TABLE items (
  item_id TEXT PRIMARY KEY, platform TEXT, source_url TEXT,
  title TEXT, price_min REAL, price_max REAL,
  category_path TEXT, json_path TEXT, collected_at TEXT
);
CREATE TABLE publish_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT, item_id TEXT, target TEXT,
  shop TEXT, mode TEXT, result TEXT, target_item_id TEXT,
  request TEXT, response TEXT, created_at TEXT
);
```

## 5. 队列与限速

单机起步不必上 Celery，用「SQLite 表 + 线程池」足够跑几千条：

```python
# 简化版 worker
while True:
    task = db.claim_next()          # UPDATE ... WHERE status='pending' LIMIT 1
    if not task: sleep(1); continue
    try:    run(task); db.done(task)
    except: db.fail(task, retry_delay=2 ** task.attempts)
```

限速器按 **(平台, 账号)** 维度做令牌桶：

| 平台 | 建议 QPS | 说明 |
|---|---|---|
| 淘宝 mtop | 0.5–1 | 单账号超过 1 QPS 容易触发滑块 |
| 1688 | 1 | 同 |
| 京东 | 2–3 | 相对宽松 |
| 发布接口 | 0.2 | 发布是重操作，间隔 5s 以上 |

规模上到万级再换 Redis + Celery + 代理池。

## 6. 多账号 / 多店铺

- `config/accounts.yaml` 存 `{platform, shop_name, cookie_file, daily_quota, qps}`
- 采集账号与发布账号分开：采集用小号（封了不心疼），发布必须用店铺主号
- 每个账号独立 Cookie 文件 + 独立限速桶 + 独立失败计数（连续失败 N 次自动摘除并告警）
