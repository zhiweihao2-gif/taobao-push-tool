# 03 · 采集接口与签名细节

> 这一篇是全项目最"硬"的部分：具体到接口名、参数、签名算法、返回结构。按此实现即可跑通。

---

## 1. mtop 通用机制（淘宝 / 天猫 / 1688 共用）

### 1.1 签名算法

```
sign = md5( token + "&" + t + "&" + appKey + "&" + data )
```

- `token` = Cookie 中 `_m_h5_tk` 的值**下划线前的部分**（`_m_h5_tk=abc123def_1699999999999` → token = `abc123def`）
- `t` = 毫秒时间戳（13 位）
- `appKey` = H5 端固定 `12574478`
- `data` = 请求体 JSON 字符串（**必须与最终 URL 里 `data=` 的字符串完全一致**，顺序、空格都要一致）

### 1.2 令牌获取流程（关键，第一次必失败）

```
第 1 次：不带有效 token 直接请求
  → 返回 {"ret":["FAIL_SYS_TOKEN_EMPTY::令牌为空"], "data":{}}
  → 但响应头 Set-Cookie 里给了 _m_h5_tk 和 _m_h5_tk_enc
第 2 次：从 Cookie 取 token 重新签名 → 正常返回
```

所以客户端要内置"**先空跑一次刷 token，再正式请求**"的逻辑，并缓存 token（有效期约 24h，过期后同样返回 TOKEN_EXPIRED，自动重刷）。

### 1.3 请求 URL 模板

```
https://h5api.m.taobao.com/h5/{api}/{v}/?
  jsv=2.6.1
  &appKey=12574478
  &t={timestamp}
  &sign={sign}
  &api={api}
  &v={v}
  &type=json
  &dataType=json
  &data={urlencoded json}
```

1688 把域名换成 `h5api.m.1688.com`，其余一致。

### 1.4 必需请求头

```
User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 ... 
Referer: https://item.taobao.com/            # 或 https://detail.1688.com/
Cookie: _m_h5_tk=...; _m_h5_tk_enc=...; cookie2=...; _tb_token_=...; 
```

`cookie2` / `_tb_token_` 来自登录态，缺失时部分接口返回 `FAIL_SYS_SESSION_EXPIRED`。

## 2. 淘宝 / 天猫 详情采集

### 2.1 主接口：`mtop.taobao.pcdetail.data.get`

```
api  = mtop.taobao.pcdetail.data.get
v    = 1.0
data = {"itemId":"<商品ID>","detail_v":"3.3.2","exParams":"{}"}
```

**返回结构（关键路径）**

```jsonc
{
  "data": {
    "item": {
      "itemId": "6xxxxxxxxx",
      "title": "商品标题",
      "images": ["//img.alicdn.com/imgextra/i1/...jpg", ...],   // 主图，5张左右
      "itemUrl": "//item.taobao.com/item.htm?id=...",
      "categoryId": "50010850",
      "rootCategoryId": "16"
    },
    "seller": { "sellerId": "...", "nick": "...", "shopName": "..." },
    "skuBase": {
      "props": [                                    // 销售属性（颜色、尺码…）
        { "pid": "1627207", "name": "颜色分类",
          "values": [ {"vid":"28320","name":"黑色","image":"//img.alicdn.com/..."} ] }
      ],
      "skus": [                                     // SKU 组合
        { "skuId": "5xxxxxxxxx", "propPath": "1627207:28320;20509:28314" }
      ]
    },
    "skuCore": {
      "sku2info": {
        "5xxxxxxxxx": {
          "price": { "priceText": "129.00" },
          "quantity": "999",
          "skuProps": [...]
        }
      }
    },
    "props": {                                      // 参数表（商品属性，非销售属性）
      "groupProps": [
        { "基本信息": { "props": [ {"name":"品牌","value":"XXX"}, {"name":"材质","value":"棉"} ] } }
      ]
    },
    "apiStack": [                                   // 内嵌的子接口结果
      { "name": "esi", "value": "{...}" },
      { "name": "descInfo", "value": "{\"descUrl\":\"//desc.alicdn.com/i3/...\"}" }
    ]
  }
}
```

> 注意：`apiStack` 在不同版本里可能是数组也可能是对象，`value` 是**字符串化的 JSON**，要二次 `json.loads`。这是最常见的踩坑点。

### 2.2 详情富文本：`mtop.taobao.detail.getdesc`

```
api  = mtop.taobao.detail.getdesc
v    = 1.0
data = {"id":"<商品ID>"}
```

返回 `data.desc` 是一段 HTML（含 `<img>` 标签）。从里面用正则抽出所有图片：

```python
re.findall(r'<img[^>]+src="([^"]+)"', desc_html)
```

图片常带 `//img.alicdn.com/imgextra/iX/...` 或 `//gd1.alicdn.com/...`，补 `https:` 前缀即可下载。部分图是 `data:image` 懒加载占位，真实地址在 `data-ks-lazyload` / `data-src` 属性里。

### 2.3 详情页降级解析（B2 兜底）

直接请求 `https://item.taobao.com/item.htm?id=<id>`，页面里有：

```javascript
window.__INIT_DATA__ = {...}      // 新版
TShop.Setup({...})                // 旧版
```

用正则截取 `__INIT_DATA__\s*=\s*(\{.*?\});` 后 `json.loads`。字段与 mtop 返回基本同构。

### 2.4 图片 URL 规则

| 场景 | 原始 | 取大图 |
|---|---|---|
| 主图 | `//img.alicdn.com/imgextra/i1/O1CN01xxx_!!0-item_pic.jpg` | 原图直接下（已是大图）；或加 `_800x800.jpg` 后缀 |
| 主图（带尺寸） | `..._!!0-item_pic.jpg_430x430q90.jpg` | 截断到最后一个 `.jpg` 之前 |
| SKU 图 | `//img.alicdn.com/imgextra/i2/..._!!0-saturn_solar.jpg` | 同上去后缀 |
| 详情图 | `//desc.alicdn.com/i3/xxx.jpg` | 直接下 |

统一处理函数：`re.sub(r'(\.(?:jpg|png|webp))_.*$', r'\1', url)`。

## 3. 1688 详情采集

### 3.1 主接口：`mtop.1688.offer.detail.get`（或 `mtop.alibaba.cbu.offer.detail.get`）

```
api  = mtop.1688.offer.detail.get
v    = 1.0
host = h5api.m.1688.com
data = {"offerId":"<offerId>","detail_v":"1.0"}
```

**返回结构（关键路径）**

```jsonc
{
  "data": {
    "globalData": {
      "tempModel": {
        "offerTitle": "标题",
        "offerId": "6xxxxxxxxx",
        "categoryId": "1033559",
        "imageList": [ {"fullPathImageURI":"https://cbu01.alicdn.com/img/ibank/...jpg"} ],
        "skuModel": {
          "skuProps": [ {"prop":"颜色","value":[{"name":"红色","imageUrl":"..."}]} ],
          "skuInfoMap": [ {"specId":"...","price":"12.50","canBookCount":"9999","specAttrs":"颜色:红色"} ]
        },
        "productFeatureList": [ {"name":"材质","value":"棉"} ]   // 参数表
      }
    },
    "detailUrl": "https://itemcdn.tmall.com/..."   // 详情图文页
  }
}
```

1688 的字段名与淘系不同（`offerTitle` vs `title`，`imageList` vs `images`），归一化层要专门适配。

### 3.2 详情富文本

`detailUrl` 是一个独立的 HTML 页面（`itemcdn.tmall.com` 或 `desc.1688.com`），直接 GET 后抽 `<img src>`。部分商品是 `//detail.1688.com/offer/xxx.html` 内嵌 iframe，需要跟随一层。

### 3.3 降级

`https://detail.1688.com/offer/<id>.html` 页面里有 `window.__INIT_DATA` 或 `iDataOffer` 变量。

## 4. 京东详情采集（最简单，无需签名）

京东 PC 详情页仍是服务端渲染，**不需要 mtop 签名**，三个接口拼起来即可。

### 4.1 主页面

```
GET https://item.jd.com/<skuId>.html
Header: User-Agent: Mozilla/5.0 ...
```

提取：

| 数据 | 选择器 / 正则 |
|---|---|
| 标题 | `div.sku-name` 文本 或 `<title>` |
| 主图 | `#spec-img` 的 `data-origin` 属性（原图） |
| 主图集 | `#spec-list ul li img` 的 `src`（缩略图，替换尺寸后缀得大图） |
| 参数表 | `#detail div.p-parameter ul.p-parameter-list li` → `{label: value}` |
| 面包屑类目 | `div.crumb-wrap .crumb a` 文本链 |
| SKU 规格 | `#choose-attrs .li` 的 `data-sku` / 文本 |
| 商品 ID | URL 里的数字 |

### 4.2 价格接口

```
GET https://p.3.cn/prices/mgets?skuIds=J_<skuId>&type=1
→ [{"id":"J_123","p":"129.00","m":"299.00","op":"159.00"}]
```
`p` = 京东价，`m` = 市场价，`op` = 参考价。

### 4.3 库存接口

```
GET https://c0.3.cn/stock?skuId=<skuId>&area=1_72_2799_0&cat=<cat>&buyNum=1
→ {"stock":{"StockState":33,"StockStateName":"现货"}}
```
`area` 是省_市_区_镇 的四段编码，固定一个即可。

### 4.4 详情图文

```
GET https://cd.jd.com/description/channel?skuId=<skuId>&mainSkuId=<skuId>
→ {"content":"<html>..."}
```
从 `content` 里抽 `<img src>`。注意京东详情图是懒加载，真实地址常在 `data-lazyload`。

### 4.5 图片 URL 规则

```
//img14.360buyimg.com/n0/jfs/t1/123/45/6789/12345/abc.jpg
                        ↑ n0=原图 n1=大图 n5/s450x450=缩略图
```
规则：把路径里的 `/n0/` `/n1/` `/s450x450_jfs/` 统一替换为 `/n0/` 得原图。

### 4.6 移动 API（可选，字段更全）

```
GET https://api.m.jd.com/?appid=item-v3&functionId=pc_detailpage_wareBusiness
    &client=pc&clientVersion=1.0.0&t=<ms>&body={"skuId":"<sku>"}&sign=<sign>
```
`sign` 为 md5 拼接（body + client + clientVersion + functionId + 时间戳 + 固定盐），实际使用中 PC 页面已够用，非必需。

## 5. 采集器实现要点清单

1. **会话复用**：一个 `httpx.Client` 持有 Cookie，token 缓存 24h，避免每条商品都刷 token。
2. **失败分类**：`TOKEN_EMPTY` → 刷 token 重试；`TOKEN_EXPIRED` → 同上；`FAIL_SYS_USER_VALIDATE` → 触发滑块，需人工或打码；`RGV587_ERROR` → IP 被限，换代理/降速。
3. **字段容错**：`apiStack` 可能是 list/dict/str；`sku2info` 的 price 可能是 `priceText` 或 `price.priceText`。写取值辅助函数 `dig(obj, *paths, default=None)`。
4. **保留原始响应**：先落 `data/raw/`，再归一化。解析逻辑改了可以离线重跑，不用重新抓。
5. **详情图不是必需的**：抓详情 HTML 成本高（多一次请求 + 大响应），批量场景可先只存 URL，发布前再下载。
