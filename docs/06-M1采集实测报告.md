# 06 · M1 采集实测报告

> 全部结论来自 2026-10-30 在本机的真实请求，不是推测。复现脚本都在 `scripts/` 下。

## 1. 一句话结论

| 平台 | 免登录可得 | 登录后可得 | 入口 |
|---|---|---|---|
| **京东** | 标题、主图、品牌、类目 ID、店铺、卖点、型号、产地、重量、UPC | 价格、详情图、完整参数表、多规格 SKU | `item.m.jd.com/product/{sku}.html`（SSR） |
| **淘宝/天猫** | 无（直接风控） | 全部（标题/主图/SKU/参数/价格/详情图） | `mtop.taobao.pcdetail.data.get` |
| **1688** | 无（滑块拦截） | 全部 | 待登录后从页面 JS 提取真实 API 名 |

**M1 的可用形态**：京东现在就能跑；淘宝/1688 必须先 `python scripts/login.py --platform <p>` 导出登录态。

  "image": ["jfs/t1/148767/39/18017/86358/...jpg", ...],   // 3 张，jfs 相对路径

### 2.3 图片 URL 规则

页面里是 `jfs/t1/.../xxx.jpg` 相对路径，拼 `https://img14.360buyimg.com/n0/` 前缀即原图。
缩略图形态 `/s450x450_jfs/`、`/n1/jfs/` 统一替换成 `/n0/jfs/`。

### 2.4 拿不到的部分及原因

- **价格**：`4??9` 是脱敏，必须带登录 cookie（`thor`/`pin`）才会解密
- **详情图**：所有 `desc` 系接口已下线，`api.m.jd.com` 需 sign
- **完整参数表**：`detail-item` 节点里放的是**配送服务信息**（免运费/配送期数/配送次数/每期数量），不是商品参数；商品参数表异步加载
- **多规格 SKU**：`newColorSize`/`salePropSeq` 由 JS 动态计算，静态 HTML 里是空的

## 3. 淘宝：登录后可用，但参数名有个坑

### 3.1 实测

无登录态：

```
mtop.common.getTimestamp           → SUCCESS（该接口不校验 sign，可用于连通性探测）
mtop.taobao.pcdetail.data.get      → RGV587_ERROR::SM::哎哟喂,被挤爆啦,请稍后重试!
```

响应体里带 `"url":"https://login.taobao.com/member/login.jhtml?..."` 并下发 `x5secdata` cookie —— **这是登录墙 + 风控，不是签名错误**。

登录后（55 个 cookie，含 `_l_g_` / `tracknick` / `_tb_token_` / `cookie2`）：

```
pcdetail 传 {"itemId": "..."}                 → FAIL_SYS_BIZPARAM_MISSED::缺少业务参数id   ❌
pcdetail 传 {"id": "..."}                     → SUCCESS                                    ✅
pcdetail 传 {"id":"...","detail_v":"3.3.2","exParams":"{}"} → SUCCESS                       ✅
mtop.taobao.detail.getdesc                    → FAIL_SYS_API_NOT_FOUNDED（接口不存在）      ❌
mtop.taobao.pcdetail.desc.get                 → FAIL_SYS_API_NOT_FOUNDED                    ❌
```

**关键结论：业务参数名是 `id`，不是 `itemId`。** 传 `itemId` 会报"缺少业务参数id"。
这个坑在未登录时看不到——风控错误会先返回，把参数错误掩盖掉。

### 3.2 返回结构（实测）

```jsonc
{
  "seller":   {"sellerNick","shopName","sellerId","creditLevel"},
  "item":     {"itemId","title","images":[...]},          // 主图是完整 https URL
  "skuBase":  {"props":[{"pid","name","values":[{"vid","name"}]}],
               "skus":[{"skuId","propPath":"-1:-2"}]},
  "skuCore":  {"sku2info":{"<skuId>":{"price":{"priceText"},"quantity"}}},
  "componentsVO": {
    "extensionInfoVO": {"infos": [                        // ← 参数表在这里
      {"title":"参数","items":[{"title":"游戏名称","text":["冒险岛"]}]},
      {"title":"保障","items":[...]}
    ]},
    "headImageVO": {"images":[...]},
    "titleVO": {"title":{"title":"..."}}
  },
  "pcTrade": {"redirectUrl": "..."}
}
```

注意：
- **参数表不在 `props.groupProps`**（那是旧版），新版在 `componentsVO.extensionInfoVO.infos`
- `skuCore.sku2info` 里有个特殊 key `"0"`，是默认/兜底项，遍历 SKU 时要用 `skuId` 精确取
- **没有 `categoryId` 字段**：虚拟类商品（如本例的皮肤代做）确实没有类目
- **没有详情图字段**：`descUrl`/`apiDesc` 均不存在，PC 页面也已是 CSR 骨架（46843 字节，无 `__INIT_DATA__`）

### 3.4 详情图：靠浏览器渲染拿到了

淘宝的 `descUrl` / `apiDesc` 接口全部下线，PC 页面是 CSR 骨架，静态请求拿不到详情图。
**唯一可行路径是开真实浏览器渲染页面**（思路来自逆向「店透视」扩展，见第 11 节）。

实测关键点（少一个都拿不到）：

1. **必须先点开「详情」tab** —— 光滚动整页只能拿到主图和页面装饰图
2. 慢速滚动 15 轮，触发全部懒加载
3. 按**图片真实尺寸**筛（在浏览器里读 `naturalWidth/naturalHeight`）：
   - 宽度 ≥ 600（详情正文宽度）
   - 宽高比 ≤ 6（排除 3456x864、708x84 这类 banner 长条）
   - 排除正方形（800x800 是主图，mtop 接口已给）
4. 优先保留路径形如 `/imgextra/iN/<卖家ID>/` 的图（详情图必带卖家 ID）

实测商品 `1073025553052` 结果：页面 114 张图 → 筛出 **11 张详情图**，尺寸
`790x1402 / 790x913 / 790x908 / 790x876 / 790x769 / 790x748 / 708x1500 / 708x1416` 等，
全部属于卖家 `2034749725`。

用法：

```bash
python run_demo.py --platform taobao --id 1073025553052 --render-desc --with-detail
```

代码：`src/collect/render.py`（`render_detail_images()`），由
`TaobaoCollector.attach_rendered_desc()` 调用。代价是每条商品多 10~20 秒。

## 5. 登录态管理（已实现）

```bash
# 1. 扫码登录，导出 cookie（人工交互，用自己的账号）
python scripts/login.py --platform taobao --shop default

# 2. 体检
python -c "from src.collect.session import SessionHealth; print(SessionHealth().check('taobao').as_dict())"
```

`SessionHealth` 判定四态：`NO_COOKIE_FILE` / `INCOMPLETE`（列出缺失的 cookie 名）/ `STALE`（淘宝 24h、京东 168h）/ `OK`。

`RiskDetector` 把平台错误串翻译成可行动的原因：

| 平台原始响应 | 归类 | 含义 |
|---|---|---|
| `FAIL_SYS_TOKEN_EMPTY` | TOKEN_EMPTY | 刷 token 重试即可 |
| `RGV587_ERROR` | RISK_CONTROL | 需要登录态 |
| `FAIL_SYS_USER_VALIDATE` / `x5sec` | SLIDER_REQUIRED | 需要过滑块 |
| `FAIL_SYS_SESSION_EXPIRED` | SESSION_EXPIRED | cookie 过期，重新导出 |
| `_____tmd_____` / `punish` | ANTI_BOT | 1688 反爬拦截 |
| 404 / 京东骨架页 | NOT_FOUND | 商品不存在或下架 |

## 7. 限速与熔断（硬性，不可绕过）

调试期踩过的坑：连续探测接口 10 几次就触发淘宝滑块，之后 30 分钟内什么都抓不到。
**限速不能靠自觉，必须写进代码。** `src/collect/ratelimit.py` 提供三层保护：

| 层 | 规则 | 触发后行为 |
|---|---|---|
| 最小间隔 | 淘宝/天猫 3s、1688 4s、京东 1.5s | 阻塞 sleep |
| 每小时配额 | 淘宝 100、1688 80、京东 400 | 阻塞到最早记录过期 |
| 熔断冷却 | 滑块 30min、风控 15min、反爬 20min | **直接抛异常，不发请求** |

关键设计：**冷却状态存在 `data/app.db`，不是内存**，所以跨进程生效——
一次触发，所有脚本（包括批量任务、调试脚本）全部停摆，不会继续加重。

熔断信号识别（响应正文匹配）：

```
FAIL_SYS_USER_VALIDATE → SLIDER_REQUIRED（30 分钟）
RGV587_ERROR          → RISK_CONTROL  （15 分钟）
_____tmd_____/punish  → ANTI_BOT      （20 分钟）
x5secdata             → SLIDER_REQUIRED
FAIL_SYS_SESSION_EXPIRED → 不冷却（重新登录即可）
FAIL_SYS_TOKEN_EMPTY  → 不冷却（刷 token 即可）
```

接入点（所有出站请求都过）：

- `MTopClient._raw_call()` —— 每次 mtop 调用前 `acquire()`，响应后 `note_body()` 熔断
- `TaobaoCollector._fetch_from_html()` / `Alibaba1688Collector._fetch_from_html()`
- `run_demo.py` —— 启动时先查冷却，冷却期内直接拒绝；批量中命中冷却立即中止

查看与管理：

```bash
python scripts/rate_status.py              # 查看配额与冷却
python scripts/rate_status.py --reset taobao   # 确认风控解除后手动解封
```

输出示例：

```
平台      状态              本小时已用    最小间隔    累计请求
淘宝      正常              3/100        3.0         3
1688      熔断 18 分钟       0/80         4.0         0
京东      正常              0/400        1.5         0
```

## 8. 视频采集（已实现并验证）

### 8.1 能采，直链就在接口返回里

淘宝主图视频放在 `item.videos[]`，`mtop.taobao.pcdetail.data.get` 一次就返回，
不需要额外接口。实测结构（商品 `1074903005877`）：

```jsonc
{
  "url": "https://cloud.video.taobao.com/play/u/2215738300422/p/2/e/6/t/1/1352964901100101.mp4?appKey=38829",
  "videoId": "1352964901100101",
  "videoThumbnailURL": "https://img.alicdn.com/imgextra/i3/2215738300422/O1CN01Px6dt7zVqBJ4Nuka_!!2215738300422.jpg",
  "spatialVideoDimension": "3:4",
  "type": "3",
  "itemId": "1074903005877"
}
```

| 字段 | 含义 |
|---|---|
| `url` | **mp4 直链**，带 `appKey=38829`，可直接下载 |
| `videoId` | 视频 ID，用于命名与去重 |
| `videoThumbnailURL` | 封面图，可当主图用 |
| `spatialVideoDimension` | 画幅比 `3:4` / `1:1` / `16:9`，发布时要匹配平台要求 |

不是所有商品都有：`videos` 为空数组就代表没有。实测交换机、虚拟皮肤两个商品都没有，键帽那个有。

### 8.2 下载的坑：CDN 会掐断流式连接

**流式下载（`client.stream`）必失败**：

```
status 200, content-length 2494780
ERR RemoteProtocolError: peer closed connection without sending complete message body
    (received 116692 bytes, expected 2494780)
耗时 150.8s，只收到 116KB
```

必须用 **Range 分片**：

```
[206] 0-524287        收到 524,288 字节
[206] 524288-1048575  收到 524,288 字节
[206] 1048576-1572863 收到 524,288 字节
[206] 1572864-2097151 收到 524,288 字节
[206] 2097152-2494779 收到 397,628 字节
总计 2,494,780/2,494,780 字节，2.3 秒     ← 比流式快 65 倍
```

实现（`MediaPipeline._download_video`）：

1. `_probe_size()` 用 `Range: bytes=0-0` 读 `Content-Range: bytes 0-0/2494780` 拿总长
   （CDN 不返回 `content-length`，只能这样探）
2. 512KB 一片循环请求，每片失败重试 3 次
3. 边下边算 sha256，写完校验字节数
4. Referer 必须是 `https://item.taobao.com/`

### 8.3 实测产物

```
data/media/1074903005877_video_test/video_1352964901100101.mp4
  2,494,780 字节
  MP4 头: b'\x00\x00\x00 ftypisom'   ✓ 有效 MP4
  sha256: c10bbf7dc04d233ee74df644a149c3db…
```

### 8.4 视频不占 mtop 配额

视频走 `cloud.video.taobao.com`（阿里云 CDN），和 mtop 是两个体系，
下载视频**不受限速器约束**，不会加重风控。只有拿 `videos` 字段那一次 `pcdetail` 算配额。

## 9. 图片管道实测

`MediaPipeline` 已在真实 CDN 上跑通，端到端产物（京东 `100008348542`）：

```
main    800x800 -> 800x800  23221B  JPEG  main_8a771c1a3b8a4991.jpg
main    800x800 -> 800x800  27517B  JPEG  main_3b34f2d42c366431.jpg
main    800x800 -> 800x800  44241B  JPEG  main_7cb464c3f34c7158.jpg
media_stats: {"total": 3, "ok": 3, "failed": 0, "bytes": 94979, "resized": 0}
```

能力：

| 项 | 实现 |
|---|---|
| 重试 | 3 次尝试（0.5s / 1.5s 退避），只对瞬时错误（网络/超时/5xx/408/425/429/空体）重试；4xx 与 `text/*` 立即判负 |
| 失败隔离 | 单图失败只写 `manifest[i].error` + `attempts`，不影响其他图，`run()` 始终返回 item |
| Referer | 按主机名最长后缀匹配：`cbu01.alicdn.com→1688`、`alicdn.com→淘宝`、`360buyimg.com→京东`，兜底 `www.taobao.com` |
| 主图 | 先居中裁 1:1，短边 < 800 用 Lanczos 放大到 800 |
| 详情图 | 宽度 > 750 等比缩到 750 |
| 格式 | webp/gif/png/RGBA 统一转 RGB 存 `.jpg`（透明贴白底）；**按 PIL 真实格式判断，不信 URL 后缀** |
| EXIF | 全清（含 GPS），字节级验证 |
| 去水印 | `crop_watermark_bottom` / `crop_watermark_right`，仅详情图 |
| 统计 | `item.extra["media_stats"]` + `media_manifest` 路径 |

实测踩到的坑：**alicdn 对 `.png` 地址会协商返回 `image/webp`**，所以 URL 后缀完全不可信；另一个固定样例 URL 已 404（返回 49 字节 1x1 占位 gif），验证脚本因此改成"先探测样例，失效则从淘宝首页发现真实图"。

验证命令：`python scripts/verify_media.py`（52 项，需联网）、`python tests/test_media.py`（46 项，离线）。

## 13. 逆向「店透视」扩展的结论（详情图方案的来源）

拿到的 CRX：`店透视-Chrome_5.0.6.crx`（2.8MB，CRX3 格式）。

解析方式：`scripts/unpack_crx.py` —— CRX3 头 = `Cr24` + `u32 version` + `u32 header_len` + protobuf header，
ZIP 从 `12 + header_len` 处开始（本例 1322 字节偏移）。

### 包内结构

| 文件 | 大小 | 实际作用 |
|---|---|---|
| `manifest.json` | 1.9KB | 申请 `<all_urls>` + `cookies` + `webRequest` + `scripting` + `declarativeNetRequest` |
| `script/content_scripts.js` | 1.3KB | 只是消息中转（`postMessage` ↔ `chrome.runtime.sendMessage`） |
| `script/service_worker.js` | 12KB | 通用执行器 |
| `popup.js` | 8KB | 跳转链接集合 |
| `source/*` | 9MB | 全是第三方库（Vue/ECharts/element-plus/exceljs/crypto-js…） |

### 核心机制

```javascript
// service_worker.js
async function localScriptLoader(files, message, sender) {
  const a = { world: "MAIN", files };          // 注入页面主世界
  return chrome.scripting.executeScript(a);
}
async function executeScript(content, message, sender) {
  const options = { function(code) { code && eval(code) } };   // 远程代码 eval
}
```

`popup.js` 里写着 `site: "https://diantoushi.com"`、`assets: "https://assets.diantoushi.com"`，
功能入口全部跳转到 `diantoushi.com/useradmin.html?type=detailTool`。

**结论：业务代码不在包里，在服务器上。插件只是一个「浏览器内远程代码执行器」。**

### 为什么这个思路能成

`world: "MAIN"` 注入后，代码拥有页面上下文：

- 用页面自己的 `fetch` → 同源、自动带 cookie、绕过 CORS
- 能读页面全局变量（mtop token、`window._itemInfo` 等）
- 跑在用户真实浏览器指纹里 → 风控识别不了
- 页面渲染完，详情图就在 DOM 里

### 我们采用了什么

代码抄不到（在远程），但**架构思路可以直接用 Playwright 复刻**，已落地为
`src/collect/render.py`，解决了淘宝详情图这个死结。

**没有采用的部分**：远程代码下发 + eval（安全风险大、不可控），我们只做本地固定逻辑。
