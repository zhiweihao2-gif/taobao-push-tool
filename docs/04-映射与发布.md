# 04 · 类目属性映射与发布链路

> 这一篇决定项目成败。采集是体力活，映射是技术活。

---

## 1. 类目映射（Category Mapping）

### 1.1 为什么不能自动

淘宝叶子类目 50010850「连衣裙」、京东 1319、1688 1033559，三套 ID 体系无任何公共键。类目树层级也不同（淘宝 5 级，京东 3 级，1688 4 级）。只能靠**映射表 + 相似度召回 + 人工确认**。

### 1.2 数据结构（`data/mapping/category_map.yaml`）

```yaml
# 源平台 → 目标平台
taobao->taobao:
  "50010850":                       # 源叶子类目
    target_cid: "50010850"
    target_path: "女装/女士精品 > 连衣裙"
    confidence: 1.0
    verified: true

taobao->jd:
  "50010850":
    target_cid: "1319"
    target_path: "女装 > 连衣裙"
    confidence: 0.92
    verified: true

1688->taobao:
  "1033559":
    target_cid: "50010850"
    target_path: "女装/女士精品 > 连衣裙"
    confidence: 0.95
    verified: true
```

### 1.3 冷启动策略（三步）

**Step 1 · 类目树落库**
把目标平台的类目树全量拉下来存表：

```
淘宝: taobao.itemcats.get          (父ID逐层拉，或 cids=0 拉根)
京东: jingdong.category.read.findByParentId
1688: alibaba.category.get
```

**Step 2 · 相似度召回**
用源类目**路径文本**（如 `女装/女士精品 > 连衣裙 > 中长款`）在目标类目树里做匹配：

```python
score = 0.6 * SequenceMatcher(None, src_leaf_name, tgt_leaf_name).ratio() \
      + 0.3 * jaccard(tokenize(src_path), tokenize(tgt_path)) \
      + 0.1 * (1 if src_root in tgt_root_synonyms else 0)
```
取 Top-5 候选。

**Step 3 · 人工确认一次，永久复用**
前端展示候选列表，人选一个 → 写回 yaml（`verified: true`）。**同一源类目只需确认一次**，后续同源类目的所有商品自动复用。这就是为什么铺货软件越用越准。

### 1.4 兜底
未命中映射时不要瞎猜，直接把任务挂起并返回"请选择目标类目"，前端弹选择框。**上错类目 = 直接被下架**，比失败更糟。

## 2. 属性映射（Property Mapping）

### 2.1 属性分三类，处理方式完全不同

| 类型 | 例子 | 处理 |
|---|---|---|
| **销售属性**（生成 SKU） | 颜色、尺码、容量、口味 | 必须映射到目标平台的标准属性 ID + 值 ID |
| **关键属性**（影响类目/搜索） | 品牌、型号、材质 | 品牌必须映射到品牌 ID；材质走值词表 |
| **普通参数**（展示用） | 产地、货号、上市年份 | 宽松映射，映射不上就丢弃（不影响上架） |

### 2.2 目标平台属性元数据接口

```
淘宝: taobao.itemprops.get?cid=<目标类目>           → 属性列表（含 is_key/is_sale/is_required）
      taobao.itempropvalues.get?cid=<cid>&pid=<pid> → 属性可选值
      taobao.itemcats.get?cid=<cid>                 → 该类目必填属性
      taobao.brand.get?cid=<cid>                    → 可用品牌
京东: jingdong.category.read.findAttrsByCategoryIdUnlimitCate
1688: alibaba.category.attr.get
```

**必做**：把目标类目的属性元数据全量缓存到本地表，映射时离线查，不要每条商品都调接口。

### 2.3 映射表结构（`data/mapping/property_map.yaml`）

```yaml
taobao->jd:
  sale_props:
    "1627207":            # 源 pid（颜色分类）
      target_pid: "1000000016"
      target_name: "颜色"
      value_map:
        "28320": {"vid": "1000000017", "name": "黑色"}
        "28321": {"vid": "1000000018", "name": "白色"}
      fallback: drop      # 映射不上时：drop | default | ask
    "20509":              # 尺码
      target_pid: "1000000017"
      value_map: {"28314": {"vid":"...","name":"S"}, ...}

  key_props:
    "品牌": {target_pid: "1000000001", type: brand}   # 特殊类型：查 brand_map
    "材质": {target_pid: "1000000002", value_map: {"棉": "棉", "纯棉": "棉"}}

  normal_props:
    "产地": {target_pid: "1000000003"}
```

### 2.4 值映射的模糊匹配

属性值常有同义词/别名（`纯棉` vs `棉` vs `100%棉`；`均码` vs `F` vs `One Size`）。做法：

1. 精确匹配 → 命中即用
2. 别名表（`config/synonyms.yaml`）→ 命中即用
3. 字符串相似度 ≥ 0.85 → 用，并记 `confidence`
4. 都不中 → 按 `fallback` 策略：`drop`（丢该属性）/ `default`（用类目默认值）/ `ask`（挂起等人工）

### 2.5 品牌映射（最容易翻车）

品牌在目标平台是**受控 ID**，乱填 = 侵权投诉 + 下架。规则：

- 源品牌能在目标平台 `brand.get` 里精确命中 → 用其 `vid`
- 命中不了 → **必须置为"其他/无品牌"**，绝不自造
- 高仿/大牌关键词（含标题里的品牌词）→ `TextSanitizer` 直接剔除

## 3. SKU 矩阵重建（SkuRebuilder）

### 3.1 问题

源平台 SKU 是「属性组合 → skuId」的扁平表：

```
propPath: "1627207:28320;20509:28314"  → skuId 5xxx, price 129, qty 999
```

目标平台要求「销售属性树 + 每个叶子一个价格库存」。且：
- 属性维度顺序必须与目标平台定义一致（有的类目要求 颜色 在前，有的要求 尺码 在前）
- 某些维度目标平台不支持（如"口味"），需要合并到标题或丢弃
- 源商品可能有 200 个 SKU，目标平台限制 100 个 → 需要截断策略

### 3.2 重建算法

```python
def rebuild(src_skus, prop_order, price_strategy):
    # 1. 按目标平台的维度顺序重排 propPath
    matrix = {}
    for s in src_skus:
        attrs = dict(p.split(":") for p in s.propPath.split(";"))   # pid:vid
        key = tuple(mapped_vid[attrs[pid]] for pid in prop_order)    # 按目标顺序
        matrix[key] = {
            "price": apply_price(s.price, price_strategy),
            "quantity": s.quantity if keep_stock else DEFAULT_STOCK,
            "outer_id": s.skuId,      # 用源 skuId 做外部编码，方便后续对账
        }
    return matrix
```

### 3.3 价格策略（可配置）

```yaml
price_strategy:
  mode: multiplier        # multiplier | fixed_add | tiered | manual
  multiplier: 1.35        # 加价 35%
  min_margin: 5           # 最低毛利
  round_to: 0.01
  psycological: true      # 129.00 → 129.90
  clamp: [9.9, 99999]
```
铺货的核心商业逻辑就在这——低价进、加价出，或者用来做引流款。

### 3.4 库存策略
- `copy`：照抄源库存（不推荐，源改了不同步）
- `fixed`：统一设 999（铺货常用）
- `sync`：定时回源同步（需要长期任务）

## 4. 文案清洗（TextSanitizer）

源标题直接搬是最常见的违规来源。规则引擎：

```yaml
sanitize:
  remove_patterns:
    - "正品"          # 无授权不得宣称
    - "官方|旗舰|专卖"
    - "最[低廉价好]|第一|顶级|国家级"   # 广告法极限词
    - "包邮|秒杀|清仓"                # 促销词，发布时不带
    - "[0-9]{11}"                     # 手机号
    - "(微信|VX|vx|QQ)[:：]?\\S+"     # 联系方式
  brand_blacklist: [ ... ]            # 与目标店铺无授权的品牌词
  max_length: 60
  fill_keywords: ["新款", "百搭"]      # 长度不足时补词
```

详情图里的水印/联系方式同理：OCR 或简单的图片指纹比对，检测到就裁切或换图。

## 5. 发布链路

### 5.1 通道一：开放平台 API（有资质时首选）

**淘宝 `taobao.item.add.v2` 关键参数**

| 参数 | 说明 |
|---|---|
| `num_iid` / `cid` | 目标类目 ID（必填） |
| `props` | 属性串 `pid:vid;pid:vid`（必填，含品牌） |
| `title` | 标题（≤60 字符） |
| `desc` | 详情 HTML（图片必须是**图片空间 URL**） |
| `price` / `num` | 一口价 / 库存 |
| `image` | 主图（图片空间 URL，必填） |
| `sku_properties` / `sku_quantities` / `sku_prices` / `sku_outer_ids` | SKU 四件套，逗号分隔，顺序一一对应 |
| `stuff_status` | 全新/二手 |
| `shipping` / `post_fee` | 运费模板 |
| `approve_status` | `onsale` 立即上架 / `instock` 仓库中 |

**图片必须先上传图片空间**：

```
taobao.picture.upload  (picture_category_id, img, image_input_title)
→ 返回 picture.picture_id / picture.picture_path
→ 拼接 https://img.alicdn.com/imgextra/iX/{picture_path}
```
`img` 参数是 **Base64 编码的图片二进制**（需 `Content-Type: multipart/form-data`，SDK 里传 `byte[]`）。

**京东 `jingdong.ware.write.add`**：字段为 `wareName` / `categoryId` / `jdPrice` / `images` / `props` / `skus`，同样要求图片先走 `jingdong.image.write.upload`。

### 5.2 通道二：后台协议模拟（无资质时）

用自己店铺登录态重放发布请求。以淘系为例：

```
POST https://item.publish.taobao.com/publish/submit   (具体路径随版本变)
Headers: Cookie: _tb_token_=...; cookie2=...; _m_h5_tk=...; 
         x5sec: ...        # 触发滑块时才有
Body: 表单/JSON，含 cid, props, title, desc, price, num, images[], skus[]
```

**实现步骤**

1. 用 Playwright 打开商家后台，扫码登录，导出 `storage_state.json`（含 Cookie + localStorage）
2. 用该状态请求一次"发布页初始化"接口，拿到页面所需的 `catId` 树、`props` 元数据、`csrf token`
3. 组装发布载荷 → 提交 → 解析响应
4. 遇到 `x5sec` / `punish` 响应 → 用 Playwright 打开验证页，人工过一次滑块，回写 Cookie

**稳定性设计**：
- 发布接口路径配置化（`config/publish_endpoints.yaml`），后台改版只改配置
- 每次发布前先做一次"探测请求"验证登录态，失效则告警
- 发布结果**必须落原始响应**，方便排查错误码

### 5.3 发布模式

| 模式 | 说明 | 用途 |
|---|---|---|
| `draft` | 存草稿箱/仓库中 | **推荐默认**，人工复核后批量上架 |
| `direct` | 直接上架 | 已验证模板的批量商品 |
| `dry_run` | 只生成载荷不提交 | 调试映射是否正确 |

### 5.4 发布结果与重试

```python
class PublishResult:
    ok: bool
    target_item_id: str | None      # 成功时的商品 ID
    error_code: str | None          # 平台错误码
    error_msg: str | None
    raw_response: dict              # 原样保存
    retryable: bool                 # 网络/限流 → True；类目错误/必填缺失 → False
```

常见错误码处理：

| 错误 | 含义 | 处理 |
|---|---|---|
| `isv.invalid-parameter:cid` | 类目不对 | 回映射层，挂起等人工 |
| `isv.missing-parameter:props` | 必填属性缺失 | 补默认值或挂起 |
| `isv.image-illegal` | 图片不合规（尺寸/水印） | 重处理图片后重试 |
| `isp.top-remote-service-unavailable` | 平台限流 | 指数退避重试 |
| `isv.permission-denied` | 类目/品牌无授权 | 换品牌或换类目，不重试 |

## 6. 全链路验收清单

发布前必须全绿的检查项（`Validator`）：

- [ ] 目标类目已确认（`verified: true`）
- [ ] 所有必填属性有值
- [ ] 主图 ≥ 3 张，每张 ≥ 800×800，无外链
- [ ] 详情图全部转存为自有 URL
- [ ] 标题 ≤ 平台长度限制，无极限词/品牌黑名单词
- [ ] 价格在类目允许区间内（部分类目有最低价限制）
- [ ] SKU 数量 ≤ 平台上限，且每个 SKU 有价格和库存
- [ ] 运费模板已指定
